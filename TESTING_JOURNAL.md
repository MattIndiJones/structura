## 2026-07-29 (suite) — Correction et revérification des constats ci-dessus

**Correction du rapport — le constat "Bloquant" sur l'accueil n'était pas un bug de l'app.** Après relecture du code (`HomeView.vue` : `openCategory()`, le `watch` réactif sur `route.query.category`, la transition CSS `category-switch-*`), tout est correct. La cause réelle : mon onglet de navigateur de test tournait en arrière-plan (`document.hidden = true`), et la transition Vue `mode="out-in"` attend l'événement `transitionend` avant d'afficher le contenu suivant — un onglet caché ne compose jamais de frame, donc cet événement ne se déclenche jamais et l'écran reste bloqué. Aucun changement de code ; à re-tester si un vrai utilisateur rapporte un jour un symptôme similaire dans un onglet réellement visible.

**Les 3 autres constats sont corrigés et revérifiés en conditions réelles (serveur redémarré, build frais) :**

- **Greeks Δ/ν ×100** ([ResultsPanel.vue](frontend/src/components/ResultsPanel.vue)) — confirmé en base de code : Δ/ν/ρ sont des ratios déjà à l'échelle "points de prix pour 1 unité de bump" (`compute_greeks`, backend), Theta seul est une fraction de prix par jour nécessitant le ×100. `gInterp` appliquait ×100 aux quatre. Revérifié dans l'UI : Δ=0,4106 → "+1% spot → P&L 0.41%" (au lieu de 41.06%), ν=-0,6151 → "-0.62%", Theta inchangé à "0.03%".

- **Watchlist ne détectait rien** ([deals.py](backend/app/api/deals.py)) — `build_watchlist_row` récupérait les prix Yahoo sur `[strike_date, today]` ; pour un deal booké aujourd'hui c'est une fenêtre de largeur nulle (yfinance `end` exclusif) → toujours vide. Élargi le fetch à `strike_date − 7j`. **Un premier correctif était incomplet** : le filtre "depuis le strike" appliqué ensuite excluait justement l'unique cas à problème (deal booké aujourd'hui, marché pas encore clôturé — aucune clôture ≥ strike_date n'existe encore). Corrigé en faisant tomber les extrema sur le dernier prix connu quand la fenêtre depuis le strike est vide. Revérifié via l'API (`GET /api/deals/watchlist`) et l'UI : sous-jacent `^STOXX50E`, WOF 100% (min 100%), barrières `M_AC_BAR` (+0.0 pt) et `M_KI_BAR` (+40.0 pts) toutes affichées.

- **Concaténation Nominal/Devise** ([DealTab.vue](frontend/src/components/DealTab.vue), [RfqView.vue](frontend/src/views/RfqView.vue)) — le focus sur Nominal ne sélectionnait pas le texte existant, donc toute frappe s'ajoutait à la valeur. Ajout d'un `.select()` au focus (revérifié par test direct : sélection 0→7 sur "1000000" après focus). Devise RFQ passée en `<select>` avec la même liste que Deal — élimine complètement la possibilité du "CHFEUR".

**Suite de tests** : 219/219 backend verts, `npm run build` OK, aucun changement commité (conformément à la règle du projet).

**Reste ouvert (Mineur, non corrigé)** : le sélecteur de templates PayScript qui se réinitialise sans confirmation visuelle immédiate — jugé trop mineur/subjectif pour justifier un changement (le script se recharge bien visiblement dans l'éditeur, c'est déjà la confirmation).
